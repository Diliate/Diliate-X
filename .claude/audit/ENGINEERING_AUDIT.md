# ENGINEERING_AUDIT.md — DILIATE X

Full audit of `Diliate` (site) and `Diliate-Portfolio` (portfolio) repos, folder by folder. Detailed component/asset/dependency/animation/SEO breakdowns live in their own reports (`COMPONENT_AUDIT.md`, `ASSET_INVENTORY.md`, etc.) — this is the top-level summary and per-folder disposition.

## Repository A — Diliate (main site)

Vite + React 18, 62 component/page files, 15MB of assets, Firebase auth, react-router, Bootstrap-adjacent (`react-bootstrap`), Framer Motion already present.

| Folder                                                                                                      | Disposition                 | Reason                                                                                                                                                                                       |
| ----------------------------------------------------------------------------------------------------------- | --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/pages/*` (services pages, home, about, blog, auth, book)                                               | **REWRITE**                 | Content architecture doesn't match V2's IA (`design-system/SiteMapSections.md`) — marketing-agency page set, not software-company. Rebuilt from scratch on new IA.                           |
| `src/components/services-component` (16 files)                                                              | **ARCHIVE**                 | Service-card pattern for the old agency offering; conceptually useful reference, not reusable code for V2's service set.                                                                     |
| `src/components/header`, `NewHeader`, `DropdownMenu`                                                        | **REWRITE**                 | New nav needs glass-on-scroll + new IA; old nav structure doesn't map cleanly.                                                                                                               |
| `src/components/footer`                                                                                     | **REWRITE**                 | New sitemap/footer links per `SiteMapSections.md`.                                                                                                                                           |
| `src/components/Button`, `custom-button` (6 files)                                                          | **REFERENCE ONLY, REWRITE** | Useful to see prior button variant thinking, but new button system (`design-system/ComponentLibrary.md`) supersedes it — token-based, not standalone CSS.                                    |
| `src/components/Preloader`, `react-spinners`, `react-preloaders`                                            | **DELETE**                  | Loading-screen pattern is dated; V2's SSR + skeleton approach (`ComponentLibrary.md`) replaces the need for a full-page preloader entirely.                                                  |

| `src/firebase/*`, `src/contexts/authContext`, `pages/auth`                                                  | **DELETE**                  | No auth/login system is in V2's scope (`PRD.md` — no client portal at launch). | `src/assets/homeimages` (15MB, several 1–5MB images)                                                        | **MIGRATE (selectively)**   | Only the logo files migrate directly (`Brand.md`). | `react-calendly` (Book page)                                                                                | **ARCHIVE**                 | No booking flow in V2 launch scope; contact form only. Revisit if a "book a call" CTA is wanted later.                                                                                       |

## Summary

Neither repo becomes the foundation. Repository A contributes almost nothing structurally (rebuilt IA, rebuilt nav, dated dependencies) but confirms brand assets (logo) and prior SEO/analytics intent to carry forward properly. Repository B contributes real, valuable UI primitives that are unusually well-aligned with the V2 design direction — these are worth a careful component-by-component migration rather than a rebuild-from-scratch, which meaningfully de-risks Phases 5–7 of `Phases.md`.
