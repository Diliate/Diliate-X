# CaseStudyTemplate.md — DILIATE V2

Interactive case study structure — cinematic layout, not an image grid. Applies to WRES, MailEngine Pro, and Sharma Pickle Store.

> CareBridge is explicitly excluded from DILIATE X in any form — unreleased project, not to be disclosed on this or any public platform. Do not reference it in copy, imagery, or metadata.

## 1. Hero

Full-bleed, product name as large display type, one-line positioning statement, key visual (product screenshot treated with glow/glass framing, not a flat screenshot dump). Scroll-cue indicator.

## 2. Overview

Quick-scan stats row (e.g., "4 user roles," "14 languages," "Real-time messaging") in the mono-accent stat style from `ComponentLibrary.md`. Sets scope before the narrative begins.

## 3. Problem

The real business problem the product solves — written from the client/user's perspective, not a feature list. This is where the "proof over promises" brand pillar (`Brand.md`) does its work.

## 4. Research

Brief — what informed the approach (market gap, user needs, technical constraints). Doesn't need to be exhaustive; a few honest sentences beat fabricated "user research" theater for a solo-built product.

## 5. Solution

The core narrative section — how the problem was solved, told through a scroll-driven sequence (per `AnimationInteractionLanguage.md`) that progressively reveals the product's key screens/flows.

## 6. Features

Grid of feature cards (icon + short description) — the concrete "what it does" list, kept after the Solution narrative so it supports rather than replaces the story.

## 7. Gallery

Curated, high-quality screenshots/recordings — cinematic framing (device mockups or glass-panel treatment), not a raw grid dump. Fewer, better images over a large unfiltered set.

## 8. Architecture

For the technically-minded visitor (a real differentiator vs. agency competitors) — simplified system diagram, key technical decisions, matches the visual language of `Architecture.md`'s own diagrams.

## 9. Technology

Tech stack badges/icons — ties back to `TechStack.md` reasoning where relevant ("why this stack" in one line per major technology).

## 10. Development Process

Timeline component (`ComponentLibrary.md`) — key phases/milestones, honest about solo-build timeline rather than implying a large team.

## 11. Challenges

What was genuinely hard and how it was addressed — this is a trust-building section competitors rarely include; keeps the brand voice's "precise, not hype" tone.

## 12. Future Roadmap

What's planned next for the product — signals ongoing investment, not a one-and-done build.

## 13. Call To Action

Contained-width CTA card: "Want something like this built for you?" → Contact.
